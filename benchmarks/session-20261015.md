## Changes made

- `scenes.py` caches independent finite-box first-hit depth images, oracle masks,
  calibrated inputs, shared acquisition times and priors. Truth is a separate file.
- `worker.cpp` uses production projection and pixel boundary extraction, then
  runs A/B/A+B with stable camera indices and two configured sigma slots.
- Equal-time and equal-sample comparisons retain explicit shortages and rejection.
  The equal-sample surface cap prevents a hidden doubling of capped surface strength.
- `instrument.py` generates an isolated equal-precision core. It changes only two
  weight denominators, independently of robust loss. Production source is untouched.
- `metrics.py` scores full pose/dimension covariance, symmetry, corners, missing
  dimensions, usability and false acceptance. It exports every request and computes
  exact binomial and scene-paired bootstrap intervals.
- `paired.py` validates cache/truth hashes and records source, binary and artifact
  identities. `test_benchmark.py` checks numerical and data-isolation invariants.
- [Operating procedure](procedure.md) provides tested pilot commands and failure handling.

## Expert decision record

Advisors: `/root/robotics_decisions` and fresh-context `/root/benchmark_advisor`.
The latter received the raw contract and source evidence without implementation
conversation history. Both reconciled the primary criteria before pilot results:
5 mm centre, 1 degree orientation, 3 mm required dimensions, 15 mm corresponding
corner displacement, 3 s goal latency and 2 s latest-capture age.
The accepted-but-wrong target is 1%, with a one-sided exact 95% upper bound.
These are engineering simulation proxies. Actual gripper clearance, calibration
distributions, robot speed and deadline ownership remain unresolved.

The advisors exposed two important experimental controls: retaining two camera
sigma slots avoids changing normalization/covariance rules, and equal raw sample
counts alone do not equalize capped information. Boundary caps remain explicitly
reported because complementary views may supply distinct observable dimensions.

## Lessons learned

- Camera count can change more than observations. The existing core selects frame
  normalization and a covariance multiplier from the configured sigma vector size.
  Stable two-camera configuration is required for this subset experiment. It does
  not establish equivalence with the separately configured one-camera M1 profile.
- Per-frame caps can hide a density confound even with equal raw points. The
  selected surface budget addresses this six-frame fixture; boundary information
  remains view dependent and must be reported separately.
  Moving-frame proportional quotas leave a small measured surface-cap imbalance,
  explicitly retained in the audit. The review resolved the generalized README
  cap wording as a low-severity documentation issue, without changing raw evidence.
- Independent truth does not make analytic boundary factors a pixel test. This
  harness extracts boundaries from rendered depth/mask bytes through production code.
  Oracle segmentation still limits transfer to real masks and sensors.
- Zero false acceptances in 200 accepted scenes cannot establish a 1% target at
  95% confidence. The exact upper bound is approximately 1.49%. More than 298
  independent accepted scenes without errors are needed, without pooling conditions.
- A user-site NumPy 2.4/system SciPy 1.11 ABI mismatch stopped the initial attempt.
  The explicit system Python stack passed. This is an environment observation,
  not a general instruction to ignore dependency conflicts.

## What could break

| Trigger | Visible result and detection | Recovery or limit |
| --- | --- | --- |
| Pixels, metadata or truth change after caching | Hash mismatch stops replay | Preserve originals and regenerate in a new bundle |
| Core weighting source changes | Exact instrumentation seam fails | Review the changed algorithm before updating instrumentation |
| Missing or ambiguous surfaces/edges | Explicit fit, support or observability rejection | Gather independent complementary views in a separate trial |
| Shared calibration bias | Cameras may agree on a wrong accepted state | Score against independent truth; agreement is insufficient |
| Missing required dimension | Incomplete geometry, not zero error | Report incompleteness and retain unresolved axes |
| Different sample strata or caps | Different exported counts and effective caps | Inspect caps before interpreting the equal-sample comparison |
| Fixed method execution order or host load | Timing drift | Do not infer small latency advantages; randomize future timing studies |
| Source changes during replay | Manifest no longer describes later binaries | Stop and create a new run; no mixed-revision evidence |

## Remaining work and limits

The pilot does not prove a fusion winner or calibrated uncertainty. Fresh 200-scene
principal-condition experiments are a separate confirmation population. The commands
are documented, but confirmation is not represented as completed by the pilot.
Same-byte ROS RGB-D/mask/TF replay, moving-wrist timestamp/TF fault admission,
goal latency and measured estimate age remain outside B1. Pixel-core age and
end-to-end usability stay null. No installed benchmark transport adapter exists.
Real segmentation, depth/calibration distributions, manufacturing variations,
hardware grasp trials and the actual picking-task limits remain unverified.
